# 初学者向けの見渡しやすさのレビュー

レビュー時点：2026-09-20。指摘への対応は[修正・検証記録](beginner-overview-changes-2026-09-20.md)を参照。以下の行番号と評価は修正前の記録。

確認日：2026-09-20。対象は `navigation.yml`、非モデル38ページの本文、モデル16ページの導入・見出し構成。モデルの詳細な計算・構造説明は短縮対象にしていない。本文・構成のレビューであり、初学者による試読や画面上の読了時間の測定ではない。教材本文は変更していない。

判断基準は「何があるのかをざっと見渡せて、目的・中心の考え方・具体例を簡単に理解できるか」。長いことだけでは問題にせず、一つの例を理解するための説明と、別の話題へ広がる説明を区別した。単独ページとして読むための短い用語の再説明は残す。

現状で目立つのは、基本説明の不足というより、概要に詳説が混ざること、同じ主題が離れた節に再登場すること、タスクと個別研究例の階層が混ざること。

## 優先度：高

### 1. 「学習の枠組み」が、自己教師あり学習の個別手法まで抱えている

対象：[教師信号と学習の枠組み](../../content/basics/learning/index.md)、特に218行以降。

冒頭の比較表はよい入口。ただし、教師あり・教師なし・強化・自己教師あり・半教師あり・弱教師ありを説明した後、マスク復元、次トークン予測、対照学習、DINOへ続く。DINOでは教師の更新、出力の成分、出力の偏りや鋭さまで扱う。学び方の違いを見渡すページから、一手法の仕組みを学ぶページへ途中で役割が変わっている。

また、比較表は製品検査なのに、教師ありではメール、教師なしでは買い物、強化学習では迷路、その後また製品検査へ戻る。同じ例で比較する利点が本文で弱くなる。

改善案：本文は各枠組みの「使える情報・何を学ぶか・一例」まで。自己教師ありの方法は短い比較とし、DINOの更新の詳説などは任意の補足にまとめる。枠組みの比較には製品検査を維持し、迷路など別の例が有効な箇所だけ切り替える。DINOの実際の結果はすでに折りたたみだが、その手前の詳説は常時表示される。

既存の再構成設計はこれらを一ページにまとめる方針なので、分割を採用する場合は本文だけでなく設計方針の変更になる。

### 3. 「学習の基本概念」の途中に前処理・理論が入り、学習と推論が離れている

対象：[学習の基本概念](../../content/basics/fundamentals/index.md)、34行、102行、132行。

モデル・特徴の次に、設備の故障予測を使った標準化・one-hot・埋め込み・欠測の説明へ移り、その後に損失と学習へ戻る。学習の基本的な流れを理解する前に、別の例と実装寄りの用語が増える。

改善案：「タスク・モデル → 学習と推論 → 損失と更新 → 汎化と評価」の流れを先に完成させる。前処理と容量の理論は後方の補足へ。はじめにとの重複をすべて削る必要はないが、同じ猫犬・背景の例を長く再開する部分は圧縮できる。

## 一律には変えなくてよい部分

- 「はじめに」は、猫犬の例を使い続け、目的・学習・利用・汎化へ進むため、今回の理念に合っている。
- 古典的な機械学習は、手法の名前だけでなく発想と用途が短くまとまっている。
- マルチモーダル、説明可能性の親ページ、検索・推薦は、目的・例・区別が比較的追いやすい。説明可能性の子ページは、任意の詳説として親から分かれているため、存在するだけで過剰とはしない。
- 確率モデルとベイズ推論は長めだが、同じコインの例で計算と意味を接続できている。DINOや複数分野を同時に抱えるページより短縮の優先度は低い。追加で軽くするなら、潜在変数・MCMC・変分推論を補足にする余地がある。
- 情報幾何は難しい題材でも、同じコインの例から進み、数式を補足に置いている。題材が難しいことだけで削除対象にしない。
- 分野固有の評価は残す。例えば時系列の時間分割、気象の雨域の位置ずれ、生命科学の未知の分子骨格は、単なる「評価は大切」という繰り返しではない。
- 安全性・公平性・プライバシー、検索・推薦、アンサンブル・MoEなどは、違いを同じページで説明できている。名前が複数並ぶという理由だけで再分割しない。

## 手を入れる順序

1. 離れた節にある同じ説明を統合する。LoRA、AlphaFold、継続学習、頑健性、転移、能動学習、配送の研究例など。
2. 基礎と逐次意思決定で、概要から外れる詳説を整理する。図や例を一律に減らすのではなく、本文の主題を絞る。
3. 自然言語・動画・3D・物理で、分野、タスク、手法、研究例の階層と順序をそろえる。
4. その後で目次順・ページ名・ページ分割を見直す。構成変更を先に大規模に行う必要はない。
