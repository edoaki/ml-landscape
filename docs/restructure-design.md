## 1. 目的と読者

AI研究をこれから始める学部生、特にB3相当の読者が、どんな研究があり、何を改善・解明しようとしているかを知るための一般公開教材とする。特定の研究室や別教材の履修を前提にしない。

到達点は、研究分野と代表的な問いを知り、主要な概念の目的・中心の考え方・具体例を自分の言葉で短く説明できること。混同しやすい概念は違いも説明できるようにする。方法の位置付けを示す目次は、その理解を支えるために使う。全モデルの内部計算を理解することや、研究テーマ・次に読む論文を選ぶことは到達条件にしない。論文選定や研究テーマ決定の演習は追加しない。

機械学習を中心に扱う範囲を明示し、AI全分野を網羅すると表現しない。古典的な機械学習は主軸にせず、一つのまとまりで簡潔に紹介する。基本概念・用途に加えて研究の広がりも示すが、個々の手法を「モデルの仕組みを知る」全体と同格の大区分にしない。

XAIを重点分野として強調しない。説明可能性は`interpretability`の一ページにまとめる。冒頭に画像と説明結果を置き、判断の手がかり・反実仮想・内部への介入を図で説明する。個別手法の計算や追加の研究例は同じページ内の折りたたみに保持し、図・出典を残す。

## 2. 全体構成

| 区分 | 読者の問い | 内容と役割 |
|---|---|---|
| はじめに | 機械学習とは何か | 猫と犬の分類を例に、学習と推論、汎化、AI・深層学習との関係を図で説明 |
| 基礎と代表的な機械学習手法 | 基本用語は何を意味し、どんな学び方や方法があるか | タスク・モデル・損失・学習の違い、訓練・評価、教師信号と学習の枠組み、確率モデルとベイズ推論、古典的手法 |
| 分野・タスクから知る | 何を対象に、何を実現したいか | 「データの種類」「選択・行動」「科学への応用」で入口を束ねる。個別項目とページの範囲は収録項目計画に記録する |
| 横断的な研究を知る | 何を改善・解明するのか | 学習・適応、信頼性・安全性、効率化・学習システム、理論・推論、データ・評価。カテゴリ数は固定しない |
| モデルの仕組みを知る | モデルは何に使え、どう動くのか | ネットワーク構造、生成モデルの枠組み、LLM、マルチモーダルモデル。基本概念と用途の後に、構造・計算を詳しく説明する独立した大区分 |

初学者が読む標準の順序を「はじめに → 基礎と代表的な機械学習手法 → 分野・タスクから知る → 横断的な研究を知る → モデルの仕組みを知る」とする。はじめにの冒頭には、用途と入出力の例から分野を見渡せる短い一覧を置く。気になる具体例へ直接進めるリンクを添え、その後に身近な例と図で機械学習そのものを説明する。標準の読む順序はサイドバーに示し、順番に読むことを各ページの理解条件にしない。モデルは興味を持った仕組みを詳しく読む入口として後方に置き、構造・計算の詳説を維持する。

標準の読む順序と、個別ページからも読めることを両立させる。必要な背景や用語の短い説明は、ほかのページと重複してもその場に置く。

線形モデル・MLPや誤差逆伝播の体系的な入門は「機械学習帳」と重複するため、この教材には専用ページを設けない。モデル・損失・更新などの役割は基礎で短く確認し、残差接続・正規化・FFNなどはそれを使うモデルで説明する。別教材の履修を基本理解の条件にはしない。

分野・タスク側は「データの種類」「選択・行動」「科学への応用」の小区分で束ねる。データの種類と応用先を排他的な分類にはせず、同じ研究が複数の入口に関わることを、はじめにの具体例で説明する。広い分野名が付いていても、一ページに固定しない。科学応用は生命・分子、物理・シミュレーション、気象予測に分ける。意思決定は基本設定、行動記録からの学習、複数主体の学習、ロボットを一ページにまとめる。概要では各設定の違いを短く示す。何ができるかを伝える代表的な動画は本文で見せ、専門的な評価や追加の研究例は補足にまとめる。世界モデルと計画、組合せ最適化は独立ページとして扱う。

Scientific MLの方法論は科学応用の物理・シミュレーションのページで、物理法則の組み込み、PINNs、ニューラルオペレーターを説明する。科学の問題と解法を別区分に離して置かない。関連するページへのリンクは、必要に応じて末尾に置く程度とする。

アンサンブル・バギング・MoEは、深層学習における複数モデル・専門家の組み合わせとして「横断的な研究を知る」の「学習・適応」に独立ページを設ける。複数の予測器をどう学び、利用時に組み合わせるかを扱い、計算削減を目的とする方法と区別する。古典の紹介にまとめず、MoEも効率化だけに置かない。予測を集約する方法と、入力に応じて専門家を重み付け・選択する方法を、同じページ内で区別する。

MoEは専門家への計算の振り分け方、VLMは画像と言語を扱うモデル群であり、同じ「組み合わせるモデル」の小区分にはしない。CLIPとVLMはモデル側のマルチモーダルモデルに置く。CLIPは独立ページで対応付けの構造と学習を説明し、VLMはCLIPを含むモデル群であることを示した上で生成型の構成例を詳説する。モデル群の用途と、内部に採用できる計算の仕組みを区別する。

### 分類と粒度

研究分野を排他的な分類木にしない。大区分は読者が探すための入口とし、対象、タスク、学習方法、望ましい性質、モデル構造が異なる軸であることを具体例で説明する。同じ概念の短い説明を複数ページに置くことは認めるが、詳説の主な置き場所は一つ定める。

横断研究は次のカテゴリに束ねる。カテゴリ数は完了条件にせず、中心的な問いに合わせて見直す。ページ名は「不確実性と未知への対応」のように主題名だけを表示し、問いを副題として付けない。本文の見出しも「確信度の校正」「判断の保留と閾値」のように、内容を直接示す簡潔な語句にする。見出しを単語一つに限定する必要はないが、説明文や長い問いかけへ言い換えない。目的・具体例・仕組みの説明は本文で行う。

安全性・公平性・プライバシーは一ページにまとめ、同じ利用場面を三つの観点から説明する。近接する概念は節として比較し、分野名ごとにページを細分化しない。セキュリティ、機械的忘却、「推論・問題解決」の区分と専用ページは収録対象から外す。RAGの説明は自然言語ページ内に置く。

| 上位カテゴリ | 主な内容 |
|---|---|
| 学習・適応 | 表現学習、転移と適応、継続・オンライン学習、基盤モデルの学習・適応、アンサンブル・MoE。教師信号は基礎、データの選択・獲得はデータ側に統合 |
| 信頼性・安全性 | 頑健性、不確実性・未知、説明可能性、安全性・公平性・プライバシー（一ページ） |
| 効率化・学習システム | 圧縮・軽量な適応、分散学習・推論実行、連合学習 |
| 理論・推論 | 情報幾何、因果推論・因果学習。学習理論と学習の最適化は基本概念に統合。理論の問いと推論方法の問いを各ページで区別する |
| データ・評価 | データの設計と品質（収集・選択・注釈、不完全・偏ったデータ、拡張・合成を一ページに統合）、評価設計・再現性 |

分野側では動画と3D・空間、自然言語とマルチモーダルにそれぞれ独立した入口を設ける。検索と推薦は「検索・推薦」の一ページにまとめる。基盤モデルの学習・適応ページはLLMを中心に、事前学習・SFT・強化学習（PPO・GRPO）・DPOを具体例とともに詳説する。基盤モデルという用語は言語だけの分類名ではないことを短く補う。自然言語では言語のタスク、LLMの利用、RAGの設計・評価を扱う。LLMのモデル自体の説明はモデル側の独立ページに置く。

LLMページには、現在Transformer内にあるGPTの入力・トークン化・表現更新・次トークンの予測と生成・学習時の説明を、図や層送り操作とともに移す。LLMからTransformerの構造・Attentionの計算へリンクできるようにし、Transformer側には構造一般の説明を残す。LLMの基本動作を自然言語・Transformerの双方へ長く重複掲載しない。具体的な移行元の節と図・参照の更新範囲は収録項目計画に記録する。

学習・適応では転移・少数例・メタ学習と環境への適応を同じページにまとめ、使える情報・更新対象を比較する。教師信号の説明は半教師あり・弱教師ありも含めて基礎の学習の枠組みに統合する。データの設計と品質では収集から能動学習・注釈・品質改善までを続けて説明し、評価設計・再現性は別ページとして残す。

モデル側ではネットワーク構造と生成の枠組みを目次の小区分から分ける。ViTは独立ページを維持し、目次上ではTransformerの下位項目にする。VLMは画像と言語を扱うモデル群として、代表的な構成と情報の流れを説明する。「構成要素を組み合わせるモデル」という広すぎる小区分は使わない。生成モデルには全体像の入口を置き、自己回帰生成の基本もその中で説明する。文章生成の詳説・系列確率・サンプリングと操作図はLLMに統合し、自己回帰生成の独立ページは設けない。VAEを主題名とする。AEの入口は表現学習にも置き、VAEのページには比較に必要なAEの既存詳説を残す。これらの小区分は組み合わせ可能な視点であり、モデルを互いに排他的な系列へ分類するものではない。

確率モデルとベイズ推論は基礎側の独立ページとし、事前・尤度・事後・予測分布を一つの例で説明する。MCMC・変分推論は入口を設ける程度とし、古典手法のまとまりや不確実性のページに基本説明を吸収しない。

### 上位カテゴリ・ページ・節

- 上位カテゴリは目次で項目を束ねる単位。カテゴリごとの概要ページを必須にしない。
- 独立ページは、一つの中心的な問いに対し、目的・考え方・具体例を単独で説明できる編集単位。短いページでもよく、長い詳説を一律に要求しない。
- ページ内の節は、同じ問いを理解するための例、方式の比較、計算や条件の説明。手法名が違うだけでは別ページにしない。

[収録項目計画](content-plan.md)を主題・上位カテゴリ・編集単位・既存内容の利用と追加範囲の対応表とする。ページに安定したIDを付け、節には親ページIDと見出しを記録する。分割する際は、別の問いとして説明が成立するか、例や前提が大きく変わるかで判断する。単なる一覧の項目数を理由に分割しない。

同計画の第2節を配置・主説明の範囲の正本、第5節を読後に説明できること・代表例・分割や統合の理由の記録とする。採用した追加項目は独立ページか既存ページ内の節かを明示する。代表例は編集案であり、素材の採用・出典確認や初学者の理解を検証済みであることを意味しない。本文の実装状況は収録決定と分けて記録する。この設計文書には原則を置き、全ページの詳細台帳を複製しない。

## 3. 説明の順序と各ページの独立性

目次と読み方の案内は、はじめに、基礎、分野・タスク、横断研究、モデルの順にそろえる。初学者には学習の基本を説明した後、タスクと研究の問いを紹介し、興味を持ったモデルの詳説へ進めるようにする。理解済みの読者は目次から知りたい項目を直接開けるようにする。

各ページの冒頭で対象の基本概念と用途・目的を説明し、そのページの理解に必要な前提を短く補う。「先に別のページを読んでください」で基本説明を代替しない。

関連リンクは任意の追加読書として末尾に置ける。標準の順序で用語・仕組み・用途を積み上げつつ、個別ページにも基本説明を残す。読了時間は実測するまで確定表示せず、固定時間に収めるために説明を省略しない。

LLMからTransformerの構造・計算へ進むリンクのように、基本動作から詳説への参照は対応する説明の近くにも置く。リンクを末尾だけに制限しない。

隣接する説明や同じ概念を扱うページでは、使える具体例を引き継ぐ。例えば同じ画像分類を基礎・CNN・表現学習・転移・データ・評価で扱い、何を変えて調べるかを示す。短い文もTransformerとLLMで共通にできる。全ページを同じ例に統一せず、各ページで必要な入力・対象・条件を短く再提示する。共有する例とページの対応は収録項目計画に記録し、既存の素材を機械的に置き換えない。

## 4. 本文の構成

### 分野紹介

基本の流れを次とする。ただし、すべてのページに同じ見出しを機械的に適用する必要はない。

1. 何を実現したいか。
2. 入力と出力の具体例。実際の画像・動画・音声・結果を説明と一緒に示す。
3. 代表的な研究と、その工夫。
4. 難しい場面、改善・解明したい問い。

関連ページへのリンクは、必要な場合のみ本文の後に添える。説明の必須段階にはしない。

「何ができるか」だけで終わらせず、同じタスクにも異なる研究の問いがあることを示す。研究の改善をどう確かめるかも、必要な範囲で短く添える。

### 理論・方法論の紹介

理論に無理に入出力デモを要求しない。「説明したい現象・問い → 小さな例 → 中心となる考え方 → どんな条件で何を言えるか → 関連研究」を基本とする。

数学的な結果は、仮定のある主張と実験的な観察を区別する。一般的な証明を読者全員の必須事項にしない。本文中で必要な用語や記号を説明する。

### 概要と詳説

各方法の冒頭は「何のためか・基本の発想・登場する研究」を説明する。その後に必要に応じて構造図、式、計算例、学習時と利用時の違いを置く。

既存のモデル詳説は資産として残す。詳説へ進まなくても、そのページの基本概念を説明できるようにする。

### 研究例の配置

現行の「具体的な研究」の事例は、原則として該当分野へ統合する。冒頭の紹介や一覧は短くする。長い説明の丸ごとの複製は避けるが、ページ単独の理解に必要な説明の重複は許容する。

全体のつながりを示すためだけの総括ページは必須にしない。

## 5. 編集形式

本文の正本はMarkdownとする。本文をPythonのHTML文字列連結から分離し、通常の文章修正にはプログラム変更を必要としない。

| 編集対象 | 正本 |
|---|---|
| 本文、見出し、通常の表、数式 | ページごとのMarkdown |
| ページID、タイトル、概要、前提知識、関連ページ | Markdown冒頭のメタデータ |
| 目次の区分と順序 | `navigation.yml` |
| 画像・動画・音声 | 該当ページの`media/` |
| 出典と素材の条件 | 該当ページの`sources.yml` |
| 複雑な図、比較表示、スライダー等の操作 | 独立した部品と必要なデータ |
| ヘッダー・目次・共通の見た目 | テンプレートとスタイル |
| 作図、生成、検証 | スクリプト |
| 公開用HTML | ビルド成果物。直接編集しない |

通常の画像にはMarkdownの標準記法を使う。複雑な図・操作に限り、少数の明示的な部品呼び出しを使う。通常の本文にJavaScriptやPythonを書く形式は避ける。

既存のPythonによる作図は必要に応じて残す。本文の編集と作図コードの変更を独立させる。生成済み素材を使って、本文編集のたびに重い素材生成を行わずに済む構成にする。

静的HTMLを生成し、既存のオフライン閲覧を維持する。数式と必要なスタイル・フォントは同梱する。外部リンクや外部サービスを使う操作は区別する。基礎的な本文・静止図はJavaScriptがなくても読めるようにする。

実装ではPython-Markdown（tables・attr_list・md_in_html）と小さな静的ビルドを採用。数式は既存KaTeXで事前組版する。閲覧時のサーバーや外部CDNは不要で、本文の編集時に作図コードを動かさない。

```text
├── navigation.yml
├── templates/
├── components/
├── styles/
├── scripts/
├── tests/
├── docs/
├── dist/                       # 生成された公開用HTML・素材
└── README.md
```

上図は責務の分離を示す案。実装ではページ専用の`components/`・`media/`を各ページの隣に置き、共通スタイルと共有素材は`assets/`に置く。既存URLとの互換性のため既定のHTML出力はルートとし、`--output dist`で独立した配布フォルダも作れる。空の素材フォルダは要求しない。

本文とそのページ固有の素材を近くに置く。一つのファイルに複数の独立したページを詰め込まず、一つの主題を一つの編集単位にする。逆に、一段落ごとにファイルを分割するような細分化もしない。

保存場所、安定したページID、公開URL、表示順を分離する。内部の関連付けはページIDを使って解決し、移動や改名でリンクが壊れにくくする。既存URLを変更する場合は旧URLからの案内を用意する。

上位カテゴリは`navigation.yml`で表し、目次の階層をそのままフォルダの階層にする必要はない。`questions/`は横断研究の保存場所とし、その上位カテゴリに属するページを保存する。収録内容・編集単位は収録項目計画、実装後の表示順は`navigation.yml`をそれぞれ正本とする。

出典には元URL、著者・題名・年、図番号や版、加工内容、利用条件、確認日など必要な情報を保存する。本文のキャプションと対応させ、同じ出典情報の二重管理を避ける。

## 7. 一般公開向けの表示

- 「06」「02〜05で学んだ内容」など、別教材の履修を前提にした表示を整理する。
- B3相当の読者を想定することと、特定研究室向けであることを分ける。研究室の重点は表示しない。
- 分野紹介の前提と、モデル・理論の詳説で使う前提を分けて示す。
- 「10系列」などの件数を見出しや共通テンプレートへ固定しない。項目追加で複数箇所の修正を必要としない構成にする。
- 日本語名と英語の検索語を併記する。
- 最新研究一覧であることを約束せず、研究例の発表年や使用した版を示す。
- 実験結果、著者の公開例、教材用の模式図・数値例を区別する。

## 8. 移行手順と検証

1. [収録項目計画](content-plan.md)の上位カテゴリ・ページ・節の区別に沿って、新しい目次を定める。読後の到達点・代表例・主説明の範囲・分割理由を確認し、カテゴリ数やページ数から編集単位を逆算しない。
2. 計画の対応表に既存ページ・節・素材・操作の具体的な移行元と実装状況を記録する。再配置、既存説明の拡充、新規執筆を分け、採用済みの追加内容を省略しない。
3. 文章、数式、静止図、動画、操作部品を含む代表ページで生成方式を検証する。
4. 共通テンプレートとナビゲーションを作り、既存本文・素材を移す。
5. 各ページが基本概念から詳説まで単独で読めるように整え、必要なら末尾に関連リンクを置く。
6. 基礎とモデルの基本説明を整えた上で、分野・タスクと横断研究の追加分を執筆する。因果推論や安全性・公平性・プライバシーなどは短い基本説明から着手する。現在の収録項目計画を基準に実装状況を管理し、除外済みの項目を過去の指定から再導入しない。
7. リンク・出典・表示・操作と、各ページを単独で読んだ場合の理解を確認する。

自動検証では、ページIDの重複、参照先の欠落、ローカルリンクと素材パス、目次の不整合、出典参照の解決を確認する。既存の計算やアニメーションのテストは、対応する機能を移した際に維持する。

PC・スマートフォン、HTML直接表示、オフライン、JavaScript無効時の基本表示を確認する。機械的な検証と、B3相当の読者による分量・理解の試読は分けて記録する。

編集した概念は、そのページの本文だけを根拠に目的・中心の考え方・具体例を短く説明できるかを制作側で確認する。必要な区別や条件が落ちる場合は本文を直す。口頭説明の試作を読者向けの演習や定型のまとめとして自動追加しない。制作者による確認と、初学者が実際に理解できたかの試読結果は区別する。

## 9. 旧設計から変更する点

| 従来 | 新しい方針 |
|---|---|
| 分野・タスクを先に並べ、読む順序を設けない | 基礎 → 分野・タスク → 横断研究 → モデルを標準の順序とする。用途と研究の問いを先に見渡し、個別ページにも必要な用語を補う |
| 言語・基盤モデル、動画・3D、ViT・VLMをそれぞれ一括 | 対象・タスクと方法の違いを目次にも反映し、説明の中心となる問いでページを分ける |
| 横断研究を粒度の異なる問いの一覧で表示 | 中心的な問いに合う上位カテゴリを設け、表示は簡潔な主題名とする。カテゴリ数は固定しない |
| 安全性・公平性・プライバシーを個別ページに分割 | 同じ利用場面を使う一ページ内の節へ統合 |
| 項目がカテゴリ・ページ・節を兼ねる | 収録項目計画で編集単位、到達点、代表例、主説明の範囲、分割理由を記録する |
| 線形モデル・MLPの体系的な基礎ページを新設 | 「機械学習帳」と重なる専用ページは設けず、研究の理解に必要な用語・役割を短く補う |
| 教師信号・転移・環境適応・データの選択を細分化 | 教師信号は基礎、転移と環境適応は一ページ、データの選択はデータの設計と品質へ統合 |
| データセット研究と不完全・偏ったデータを分割 | データの設計と品質の一ページにまとめ、評価設計は独立して扱う |
| Transformer内でGPTの入力から生成まで詳説 | LLMの独立ページへ図・操作とともに移し、Transformerの構造・計算へリンク |
| 各ページで具体例を選び直す | つながる説明で使える例を引き継ぎ、各ページにも必要な条件を再提示 |
| 科学応用・意思決定をそれぞれ一ページに収容 | 問い・例・前提の違いに応じて独立ページへ分ける。Scientific MLは科学応用内に維持 |
| ベイズ学習・確率的推論を古典の一節に収容 | 基礎側の独立ページにし、確率モデルから観測による推定を説明 |
| XAIを研究室の重点として強調 | 他の研究分野と同じ原則で扱う |
| 古典手法は任意の補足 | 古典のまとまりで基本概念と研究の広がりを簡潔に紹介。主軸にはしない |
| 最後に具体的研究例をまとめる | 各分野の説明へ統合し、入口では短く紹介 |
| Python内に本文・HTML・図が混在 | Markdown本文、テンプレート、図・操作を分離 |
| 登録順がそのままページ順 | 目次・保存場所・URLを分離。複雑な読書経路は設けない |

旧設計にある個々の素材・図の指定は、この変更に直接抵触しない範囲で引き継ぐ。構成変更を理由に、以前取り除いた説明図や演習を自動的に再導入しない。
